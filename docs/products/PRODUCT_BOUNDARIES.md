四个产品拥有独立页面入口、用例、权限范围、任务状态与发布节奏。用户工作台围绕 Case 工作，研究侧围绕 Dataset/Sample/Revision 工作；不能让任一产品直接修改另一个产品的私有数据库记录。

共用能力通过版本化包或 API 暴露：dataset-contracts、model-gateway、renderer、job-runtime、asset-store。共享代码的前提是职责和契约稳定；当前不预建空服务，也不要求立刻部署分布式系统。

agentic 是可选推理能力包，不是第五个面向用户的产品。是否用于合成、辅助审核或案件分析，由各产品经公开接口选择。

## 评测台规格

- 模型区：勾选一个或多个配置、添加/编辑模型、声明文本/图片能力、分别测试连通性。记录实际 endpoint、模型标识、协议、请求参数快照和凭据引用；密钥不进入结果或日志。
- 模式区：文本、图片、图文、多图及现有任务轨道；不同模式有独立输入构造器。传给模型的输入不能混入隐藏答案或 reviewer-only 标注。
- 范围区：固定 DatasetRelease，按版本、批次、数据类别、任务类型、标签、显式样本 ID 或固定种子的抽样选择范围。冻结实际输入 ID 和哈希，运行期间不跟随 latest 改动。
- 运行区：展示模型×样本×任务的总量、完成/失败/取消、并发、耗时、重试次数和预算。失败项可筛选、导出或按范围重试；新运行保留与旧运行的关系。
- 错误区：区分鉴权、限流、超时、网络、输入不支持、响应解析、Schema、来源文件和评分失败；显示脱敏详情、request/task/run ID 和可重试状态。
- 结果区：逐题结果与引用、原始响应的受控保存、按任务/类别的质量指标、成本与延迟分布、模型对比、混淆矩阵（适用分类任务时）和失败分布。
- 评分状态：没有有效金标的任务标为未评分/待审核，不把缺失结果当作零分。法律实质质量与程序测试通过分别记录。

评测任务至少保存 EvaluationRun、ModelSnapshot、DatasetRelease、TaskAttempt、EvaluationResult、MetricReport；恢复必须沿用原始快照，不能不知情地换模型或换数据。

## 合成生成台规格

- 从可追溯来源和生成约束创建批次；选择模型、语言、平台、数量、任务类型、模板和渲染参数。
- 固定 source/prompt/template/renderer 版本，保存生成响应与验证结果；模型随机性不因保存 seed 就被宣称完全可重现。
- 把生成、结构校验、渲染、产物打包作为有状态阶段；阶段失败可检查和恢复，已验证产物不重复生成。
- 生成候选交给审核台；候选不会自动成为可发布金标。
- 渲染输出包括页面图片、message ID 到 bbox 的映射、尺寸、哈希和参数 manifest，不能只导出一张脱离文本版本的图片。
- 可优先复用 legalhub/synthesis.py、tools/render_v2_round2.py、相关 blocks 与既有模板；由适配器包装旧入口，逐步解除全局变量/路径耦合。

## 数据审核台：保存、渲染和断电恢复

审核默认先展示图片与消息坐标框；点击消息弹出文本编辑及评论。坐标默认锁定，解锁后可拖动与缩放，保存后按版本真实重渲染。判决书原文使用始终可打开的侧栏，无原文也明确保留缺失区块。评论可独立保存，不要求改消息；同源数据生成时可选用并固定评论快照。见 [图片审核操作与契约](REVIEW_CANVAS.md)。

浏览范围包括来源原文、聊天/消息、原件/派生图片、问题/答案、任务类别、标签、来源引用、各轮版本和审核状态；列表数量按类别与版本统计，支持过滤、逐项导航与原图/文本对照。

这里的“审核纠正”与用户工作台的案件备注编辑是两项独立业务。合成聊天文本的纠正必须生成对应的新渲染；真实原件保留原貌，转录纠正或校正版视图作为独立派生版本保存。

### 状态与存储

| 状态对象 | 作用 | 持久化要求 |
| --- | --- | --- |
| LocalDraft | 键入中的未提交修改 | IndexedDB，按用户/数据集/样本隔离，保存 base_revision 与 draft ID |
| ServerDraft | 跨刷新/进程恢复的草稿 | 防抖保存，带版本比较；不触发正式重渲染 |
| SampleRevision | 点击保存后的权威数据版本 | 数据库事务提交；携带 parent revision、编辑者、字段差异与标签 |
| RenderJob | 保存触发的待渲染任务 | 与 SampleRevision 同一事务落库；不能只放内存或浏览器缓存 |
| RenderCheckpoint | 完成到哪一页、文件哈希与参数摘要 | 每个可恢复单元完成后提交，重启时校验产物再跳过已完成部分 |
| RenderManifest | 可发布的图片/bbox/文本版本映射 | 全部成功后原子切换；保留前一成功版本 |

### 保存后立即反映到渲染的协议

1. 前端显示本地草稿是否已缓存；显式保存携带 expected_revision 和 idempotency_key。
2. 同一数据库事务写入 SampleRevision、标签变更和 RenderJob，成功后返回新 revision 与 job_id。
3. UI 显示“文本已保存 / 渲染排队或进行中”，不能把旧图标为已更新。通过轮询或 SSE 跟踪对应 revision。
4. Worker 使用新 revision 的快照渲染；每页写临时文件并完成校验后再记录 checkpoint。
5. 全部完成后生成新 manifest，以 revision 比较原子发布；图片 URL 带 revision/hash，避免浏览器继续命中旧缓存。
6. 文本改变导致 bbox/分页/任务引用变化时重新生成关联映射；受影响的审核状态或题目答案标记需要复核。
7. 渲染失败保持已保存文本和失败日志，提供重试入口；保留上一成功图并明确显示版本落后。

新版本尚在渲染时又保存更新版本，旧 Job 完成也不能覆盖最新 revision 的预览。Job 幂等键至少包括 sample_id、revision、renderer_version 和参数摘要。

### 断电、断网与恢复验收

- 数据库使用受控事务、持久化日志和明确的同步配置；任务只有落盘后才能向 UI 宣告已保存。
- Worker 使用有期限的任务租约；异常退出后可重新领取任务，并从已验证 checkpoint 恢复。
- 图片和 manifest 先写临时产物，完成后原子发布；半写入文件不能被当成成功。
- 网络上传需要分片时，UploadSession 保存分片序号、大小和哈希；恢复只补缺失分片，合并后检查完整哈希。
- 草稿恢复与服务器当前 revision 对照，出现冲突保留双方内容，由用户合并，不静默覆盖。
- 生成/模型调用断电后的费用与结果未知状态单独记录，不能把未知结果当成功，也不能无限重发外部计费请求。
- 必须测试：键入后刷新、保存后杀进程、渲染一半杀 worker、重启后继续、重复点击保存、旧任务晚完成、文件损坏、浏览器缓存旧图和两人并发纠正。

上述协议现已在研究侧独立实现。当前验证覆盖子进程强制退出、分页恢复、损坏文件、旧任务晚完成、IndexedDB/服务器草稿及并发纠正；分片上传与真实物理断电仍未验收。详见 [研究产品 MVP](RESEARCH_MVP.md)。

## 用户工作台 MVP：本轮实现

默认入口只包含四项导航：

1. 概览：案件信息、工作摘要/备注、证据与转录/事件数量、原件链接。
2. 编辑：案件名称、工作摘要、备注；显式保存到服务器，带 revision 乐观锁。原导入 description、来源记录和原件保持兼容。
3. 证据时间线：直接展示证据图片，每张图片只出现一次；利用关联记录中的已有时间排序，必要时显示时间范围，未知时间明确保留。支持图片名称/时间搜索、时间筛选和点击查看原图，不展示转录文字条目，也不要求预先启动分析。
4. 生成 PPT：模拟按钮与模拟后端返回；显示模拟完成，不提供不存在的下载文件。未来替换 PresentationGenerator 即可接入真实 API。

案件编辑的草稿按登录用户与案件隔离缓存在本浏览器，刷新可恢复；成功保存后清除草稿；冲突或失败时保留。页面提示缓存失败时不宣称内容已保护。它不等同于审核产品的跨进程渲染恢复能力。

新增接口：

- GET /v1/cases/{case_id}/workbench：授权案件、原件与时间线快照。
- PUT /v1/cases/{case_id}/workbench：保存案件工作信息；expected_revision 冲突返回 409。
- POST /v1/cases/{case_id}/presentations：返回 status=mock、provider=mock、download_url=null。

源码落点：backend/domain/workbench.py、application/services/user_workbench.py、api/workbench.py；frontend/features/workbench 与默认 App。旧版 App 独立保存为 LegacyApp，通过 console.html 启动。

## 实现顺序

用户工作台 MVP 后，本轮已依次完成数据审核的“纠正 → 保存 → 真实渲染 → 进程恢复”切片，以及合成生成台和评测台。三个研究产品复用版本化资产契约与任务库；质量评估记录及质量 Prompt 统一由审核台管理，生成 Prompt 与 Markdown 迭代由生成台管理。

各产品的前端、业务和存储应按独立应用组织；共享渲染、模型协议和任务库通过契约复用。物理目录迁移在入口和持久化兼容验证后进行，不将旧文件批量移动来代替产品拆分。
