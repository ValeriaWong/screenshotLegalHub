# KIE → IoU → VQA 验收策略

2026-10-25，执行状态v3。A/P0–P5的软件验收已执行；B的9项仍计划中，G3在线与G4人工研究有效性未通过。[开发计划](../ai_docs_center/KIE_VQA_PIPELINE_PLAN.md)限定范围；[原43项草案矩阵](../../reports/kie_vqa_pipeline_plan_revision_20261024/acceptance-matrix.json)保留原条件，[本轮逐项软件证据](../../reports/kie_vqa_pipeline_implementation_20261024/acceptance-evidence.json)区分自动化覆盖和待人工评审。

## 1. 四个独立验收结论

| 门槛 | 证据 | 可以宣布什么 | 不能替代什么 |
| --- | --- | --- | --- |
| G1 契约/确定性 | 人工期望小例、6333旧明细精确回放、白名单/身份/分母测试 | 算法与输入契约实现符合冻结规则 | 真实网络/供应商兼容、模型质量 |
| G2 隔离完整流程 | 模拟HTTP实收计数、临时SQLite、真实子进程崩溃、全量manifest演练、UI/审计/兼容与性能 | 本地自动串联、恢复和报告可用 | 实际在线服务已成功运行 |
| G3 小批真实在线 | 明确3图/6题、最多9调用的实际manifest与原始响应、每步绑定/IoU/输入/账本 | 指定模型/时间/协议下至少一条在线链路真实走通，其余任务均有终态/原因 | 正式准确率达标、全量稳定性、论文等价或法律认证 |

## 2. 测试夹具与独立期望

A组人工期望夹具至少含三张不同尺寸/方向的简图：同图多个消息、两类区域、同一区域多个属性、并列框、额外预测、无消息/空conversation、同名不同图、同SHA不同逻辑来源。预期匹配/原因/输入由人可直接检查的坐标和文本写出，测试不能调用待测匹配器生成自己的期望。

B组旧回放使用已冻结原始KIE与标注和6333行保存结果，保留原浮点。单独检查102无消息、零交集、原阈值0.6下1475通过以及29个bug_report身份。边界阈值使用实际epsilon公式得到独立数值期望，不以直觉把几何0.6当成分母加epsilon后的0.6。

C组协议夹具放入只出现在target/review/source中的canary，另用正常图像字节，验证预览与mock服务实收请求都不泄漏。覆盖transfer/file/image字段，不借“只保留content”丢失任务内容。对话中伪装的系统指令视为数据。

D组模拟HTTP服务使用持久化请求计数/请求hash/阶段和故障开关，支持返回前后分别挂起、断连接、格式坏、usage缺失、401/429。演练不访问真实模型域名；fixture文字与真实材料分开。进程崩溃必须杀实际worker子进程后重启，不能仅通过抛异常代替全部崩溃测试。

E组全量本地fixture沿用当前manifest：1170 KIE＋6304区域VQA＋4698全局VQA，4180个关联区域，29旧评论单列。82候选/410相关任务保持身份待核对标签，不替其“审核通过”。全局视觉题预先独立规划，不因KIE失败误阻塞；只有选择文档预测诊断才受其KIE依赖。

## 4. 故障窗口与付费判定

| 注入窗口 | 恢复期望 | 额外模型调用 |
| --- | --- | --- |
| 计划保存后、未派发 | 恢复已冻结节点，不重复建计划 | 仅计划中尚未发送项 |
| 本地解析/匹配/输入/评分中 | 校验raw和产物SHA，只补本地；损坏产物重新本地生成 | 0 |
| 请求意图已落盘、是否发出不明 | 依赖实收计数/请求证据，无法证明则保守unknown | 默认0重发 |
| 服务已收到但返回未落盘 | unknown；不声称未计费，需显式重试另建attempt | 默认0重发 |
| Gateway返回已落盘、节点投影未提交 | 校验归属/请求/输入hash后采用raw，完成本地与outbox | 0 |
| 阶段终态与outbox提交后崩溃 | 后代节点只创建/运行一次，迟到旧租约不能推进 | 不重复已发送项 |
| 新KIE重试成功 | 新分支生成新Match/Input；原VQA仍绑定旧预测 | 仅显式授权的失败KIE和新后代预算 |
| 只更换参考答案/量表 | 新ScoreSet包含新target/hash/规则，旧分数保留 | 0 |

对供应商不支持幂等的网络请求，不宣称严格exactly-once；软件验收要求普通恢复不主动重复未知请求，且所有可能计费窗口可查。模拟服务计数器是实际发送次数的独立证据，不能只数数据库attempt行。

## 5. 统计守恒与分母

每图KIE、每区域关联、每题/轨道VQA分别计数，不把三者相加称作题量。题目是否计划先于推理冻结。

VQA执行状态采用互斥主状态：pending、ready、running、response_received、service_failed、unknown、cancelled、blocked_upstream、blocked_no_match、invalid_input。任意时刻各状态数量之和=该轨道N_planned；终止后pending/ready/running必须0；aborted也须将未发送项明确置为cancelled或相应阻塞终态。在途结果无法确认则置unknown。paused只是未终止的暂停，可以保留待处理节点，但不能宣称完成。低IoU题计blocked_no_match，全局题关联为not_applicable，KIE解析错误和服务错误不能混为同类。

结构状态（valid/invalid）、参考状态（reviewed/legacy_unverified/invalid）、评分状态（scored/unscored/rubric_pending等）是另一组维度，可与执行状态重叠，不能再加到同一终态守恒式中。父流程completed_with_issues与“答案正确”无关。

- 服务覆盖：收到响应数/N_planned，另列unknown/服务失败与取消数。
- 区域关联覆盖：达到固定阈值且依赖有效的区域题数/计划区域题数；区域级覆盖另报4180类单元，不代替属性题覆盖。
- 参考有效题数N_ref在冻结参考版本后确定；模型输出坏/拒答不会使一个有效参考失效。身份字典或金额目标无效时，即使输出坏JSON也不自动补0分，分别记录参考和格式问题。
- 匹配后条件质量：仅在协议明确、参考有效、已收到回答的匹配题上计正确数/该固定条件子集；格式错/明确弃答依预先规则记0，服务未知另列。必须并列其相对N_planned的覆盖，不能单独宣传条件准确率。
- 完整链路正确产出率：评分完备时正确输出数/N_ref；没有正确产出的失败/阻塞/取消仍在分母，这是运行效果指标，不解释为模型法律能力。无效参考/不支持的语义另列，不能用其补0或隐藏。
- 同模型/题目配对的整图与匹配文本比较，需显示KIE生产者与VQA模型、参考引导身份、样本/输入/Prompt/评分/ScoreSet哈希；模型A的KIE＋模型B的VQA不能标成B独立端到端成绩。
- 固定分类字典定义macro-F1标签空间和零支持类处理；无效预测不能偷偷增加一个新合法标签。混淆矩阵和分数使用同一ScoreSet目标，不能拿新分数配旧target。
- 金额/身份/分类/开放量表分开汇总；模型裁判分、人工评分、原文精确匹配和归一化诊断不能无说明混成平均分。未知费用及缺失usage保持null/partial。
- 评分完整性：另报N_scored_ref/N_ref；存在已返回但待判定的有效参考答案U时，已确认正确数C对应区间[C/N_ref, (C+U)/N_ref]，这是待评分的不确定区间，不是统计置信区间。失败/阻塞并无已交付答案，不能假装属于U。未完成评分不得把下界包装成最终模型质量或据此排名。

## 6. 性能与完整回归

P5使用当前12172任务manifest进行一次不访问在线服务的完整计划/执行演练，记录机器、Python/Node/SQLite版本、数据规模、并发、冷/热状态和耗时。拟议软件门槛：本地计划展开≤30秒；20次主要状态/列表请求p95≤2秒；一次轮询不携带raw/base64或全量任务；默认进度刷新≤5秒。标准是本项目拟议门槛，尚未实测，不是对机器性能的既有承诺。

此外检查高扇出时的预算预留和lease heartbeat不被本地计算/全表扫描饿死，限定并发/内存并记录峰值，不把无限排队当成可扩展。超限先剖析索引、manifest分页和阶段I/O；未解决不得写“规模验收通过”。

## 9. v2新增验收方法与第二轮批判性限制

F组防泄漏性质测试：固定图片、独立问题、保存预测和mock响应，只改变评分侧参考框/答案/人工归属/标注顺序，断言e2e_image和B1所有解题输入、候选、预测裁剪、路由和请求hash不变；允许评分变化。参考引导方式不符合此性质是预期身份，不能篡改标签冒充端到端。此测试不能证明问题没有语义泄漏，另由盲化题目审核确认；隐藏文件名/标注ID也纳入解题投影白名单。

G组粒度/证据夹具：金额小框在大卡片内、巨大整图预测框、重复金额、头像归属、跨消息转账、候选漏召回、真实但不支持答案的引用、虚构引用ID。输出后才读取人工参考做错误归因；不得将诊断反向用于解题。类型/parent金标未齐时只测软件契约，不能生成真实检测/证据成绩。

H组补救/费用夹具：相同计划分别启用和关闭预先固定的补救；保持首次输出，记录触发信号、各次输入/输出、选择规则和全部费用。最多调用次数覆盖所有额外步骤；取消、预算不足、unknown仍服从既有停止规则，不借补救自动重发。partial与strict不同版本、不同输入和成绩，不混合成一个胜出分数。

I组研究与界面验收：20图开发集在看到新输出前固定，按对象类型/歧义分层；同案件/同图及近重复关联组不跨开发与留出。候选数量、阈值、Prompt、重试/补救在开发集定版；正式比较用同一问题版本/固定ScoreSet。题多的图片会主导逐题均值，因此并列按图汇总及题型分层；置信区间或重采样以案件/图片关联组为单位，样本不足就只作描述，不将11002相关题当11002次独立观察。

参考引导与无参考方式差异仅提供瓶颈线索，不能直接认定差值等于定位误差；问题改写、上下文、成本和模型组合都可能变化。比较需固定数据/题目并披露这些差异。另以冻结的简单整图回答/确定性检索作基线，不能只比较复杂方案自身迭代。

LLM裁判由审核台保存规则、Prompt、意见/理由/版本和人工裁决；开放题需测人工一致性和争议，确定性字段优先规则评分。未校准裁判、单模型自评、多模型多数票均不代签金标。参考依据：[覆盖率与错误率权衡](https://jmlr.org/papers/v11/el-yaniv10a.html)、[LLM评审偏差研究](https://arxiv.org/abs/2306.05685)；本项目的阈值/用例/交付顺序是拟议工程决策，并非论文提供的既定标准。
