## 迁移边界

四条轨道分别保存：KIE整图抽取、图片VQA、KIE预测文本辅助VQA、人工转录辅助诊断。辅助诊断不进入纯视觉成绩。区域定位VQA明确允许提供框；KIE整图抽取不提供金标框。整图、多图、定位区域不得由金标message_ids隐式筛选后混称同一输入协议。

本次指定目录没有完整的案件级多图题集；当前项目另存的154组案件多图题及17,672八轨任务另设扩展批次，不混入本次12,201条准备记录的分母。

## 必须保留的绑定

每个任务冻结源文件SHA/JSON指针、逻辑图片ID与字节SHA、样本修订、区域/标注版本、输入和输出schema、Prompt、评分器及参数、模型配置。串联VQA再绑定实际KIE预测哈希；上游失败记blocked_upstream，不能偷偷改用人工转录。

原始响应先落库，再解析/校验/匹配/评分。人工修改金标或评分规则生成新版本，旧回答可以离线重评，旧分数不覆盖。历史调用缺少usage/请求号保持未知，不补零费用。源数据原操作者未知时不伪造，记录实际迁移者及来源。

## 正式运行前仍缺的材料

- 人工消息级KIE参考框/字段及头像ID映射；现存450条模型结构化输出不能代替。
- 旧VQA提示构造器和评分实现（若要求论文分数等价复现）；现有v1主入口有缺失函数，v2与保存问句不一致。
- 标签字典、case-family划分、任务输入范围和开放题评分量表；法律维度按V3要求单独复核。
- 已审核发布的目标快照、模型配置、最大调用/成本及停止/显式重试规则。当前410准备行因主图缺失被标记，并不等于它们不可恢复。

这些缺口不阻止已交付的本地软件桥接；新协议正式计分和V3研究验收仍按各自门槛进行。本轮真实模型调用0，业务代码和实际SQLite已按上述范围迁移；原590研究记录/2687案件/111已绑定附件及1132源文件保持。V3阶段4/8、独立认证0保持。

## Prompt、质量记录与产品边界

KIE抽取和VQA答题模板在评测任务配置中保存Markdown版本、父版本、改动理由及输入/输出协议，运行时冻结。模型质量评估/裁判Prompt及人工审核、纠错、评论仍由审核台管理，保存过程、结果与修改意见；生成Prompt继续由合成生成台管理。评测台读取这些已冻结版本，不直接改其他产品私有记录。

反馈可用于开发集的下一版Prompt和生成，但已用于修改题目/规则的样本不能再作为独立留出集。新旧模板、人工转录辅助、模型预测辅助与纯视觉成绩分别比较，不能混成一个提升分数。
