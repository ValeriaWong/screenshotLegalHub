## 现在怎么试

1. 左侧“会话”选择全部或指定会话；原图目录和时间轴均显示名称。
2. 点击原图消息：左侧保留截图和引用框，右侧显示解释。右栏可切换“会话上下文”和“合同内容”。上下文不再追加到截图下方。
3. 点击右侧逐字引用，左侧定位对应原图；跨图、跨会话节点保留各自名称。
4. 切换“法律大事记”，查看法律类型、具体行为、判断条件、证据状态及引用。
5. 切换“合同内容”，查看8项条款要素及缺口；点击条款进入左右核对。
6. 右上角选择中文 / English。切换保留当前选择，刷新后保留语言偏好。

桌面核对两列分别滚动；手机也保持左右两列，可使用“放大”阅读原图。

## 法律节点与具体行为

4个普通事实节点独立保留。法律大事记改为8个有逐字依据的审阅节点：

| 法律类型 | 具体事情 | 当前状态 |
| --- | --- | --- |
| 要约邀请 | “卖衣服哦，欢迎来看看” | 候选 |
| 授权范围审查 | “你选吧”结合“你挑两件 我看看” | 待核实 |
| 要约邀请 | 展示服装材质与保暖特点 | 候选 |
| 要约审查 | 询价及随后被遮挡的回复 | 待核实 |
| 承诺审查 | “双面羊绒的”之后回答“好，稍等一会” | 待核实 |
| 付款履行线索 | 索要支付宝，陈述转款2000及第三人付款 | 原文陈述 |
| 补款 / 变更审查 | “不够你再跟我说哈” | 待核实 |
| 受领确认 | 问钱是否收到，对方回答“收到了” | 原文陈述 |

顶部展示要约邀请、要约、撤回、撤销、承诺、反要约、合同成立。撤回、撤销、反要约没有明确依据时显示“现有材料未见”，不生成虚构事件。“未见”不意味着该行为从未发生。

撤回、撤销、承诺及实质性变更构成新要约的条件，分别参考民法典475—480、488—489条；来源为 [最高人民法院公布的民法典](https://www.court.gov.cn/zixun/xiangqing/233181.html)。页面提供原始法条、来源及适用版本未核实说明。

报价遮挡、身份、完整约定、实际支付及交付仍待核实。没有把“好”直接当作承诺，没有把2000补为成交价，没有把收款确认当作全部清偿；价款信息不完整也未被视作合同必然未成立。

## 合同内容与语言

新增当事人与角色、标的、数量、质量 / 规格、价款、支付、交付、变更 / 补款8项要素。记录现有内容、证据状态、解释与缺口，并链接原文和法律节点。交付约定缺失时不伪造引用。这是条款证据视图，不是确认已经成立的合同。

i18n 包含界面、法律节点、合同要素、当前6项复核解释及待核事项。原始证据、会话专名及法条原文保持原语言。未来模型生成的未知文本没有对应翻译时保留原文；本轮没有自动翻译服务。已知英文法律检索词由代码映射，例如 receipt confirmation 与收款确认返回同一组结果，任意英文查询不会被假定已经翻译。

## 产物与模型来源

新增 `legalhub/case_presentation.py`，由本案注册消息解析会话、法律节点、合同内容及双向引用。助手对照原文的展示补充独立保存于 `blocks/evidence/artifacts/casework/presentation.json`，校验案件、图片摘要及转录来源摘要，不覆盖原图、转录或模型响应。

当前保存的复核版为 `95fc6969a6da4e3f`；模型原稿来自 `3f49d1fff65b469e` 的 Qwen/Qwen3.8-27B 真实响应。原模型请求版本为 case-meaning-v4-stream，保存的复核索引使用旧版材料指纹。此次法律节点与英文文字归属助手原文审阅，不冒充新模型输出。

以后重新生成使用 case-meaning-v6-legal-stages，补充撤回、撤销、反要约、成立类型及参考法条。提示词升级允许读取同一来源的保存复核结果；材料或转录改变会失效。新提示词尚未进行本轮模型效果评测，不能据此声称自动法律理解质量已达标。
