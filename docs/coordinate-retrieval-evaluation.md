## 哪些环节由代码完成

| 输入情况 | 定位与检索方式 | 边界 |
|---|---|---|
| 本项目生成的HTML截图 | 渲染时读DOM矩形、转换像素坐标、记录image/message关联；已生成清单可直接导入 | 不需要视觉模型猜坐标；原图、样式和框必须同一版本 |
| 已有历史矩形标注的图片 | 按原图字节SHA256匹配，转换xywh→xyxy、校验尺寸和边界 | 保留原标注来源，不擅自提升为本轮金标 |
| 未标注的新上传图片 | 可用图像处理+本地OCR提取候选文字/区域，随后校验 | 单凭文件无法还原消息位置；OCR通常也使用识别模型，不能宣传“完全无模型” |
| 已有转录的文本检索 | SQLite FTS5/BM25，按案件过滤，返回绑定source_refs的消息 | 不调用生成模型，但索引内容可能来自作者转录、OCR或历史模型预测，需保留来源状态 |
| 点击检索结果回到原图 | source_ref→evidence_id→SHA256/原件→bbox，缩放只改变显示比例 | 能打开原图和框，不等于该引用支持结论 |

在仓库根目录执行：

```powershell
$py = '.\product_v1\.conda\screenshotlegal-v1\python.exe'
& $py -B -X utf8 product_v1/tools/sync_evidence_regions.py --output reports/coordinate_audit_20261024/preflight
```

## 推荐的最小评测组合

三个层次独立计分，不合并成一个难以解释的总分：

| 层次 | 首选指标 | 补充指标与适用条件 |
|---|---|---|
| 问题指定的消息定位 | Hit@IoU≥0.5、Hit@IoU≥0.75；全目标mean IoU，漏框/错图为0 | 多框时同时报一对一匹配的Precision/Recall/F1，防止乱报大量框 |
| 全图目标检测 | AP50、AP75、AP@[0.50:0.05:0.95] | 适合完整目标集、类别和有排序分数的检测结果；无可靠confidence的单框VLM任务不强行以AP为唯一主指标 |
| 代码检索 | Recall@5、Recall@10；MRR@10 | 有分级相关性时用nDCG@10；多跳题增加CompleteSupport@k |
| 回溯结构 | 来源可解析率、同案/同图/哈希一致率、合法坐标率 | 全部可用代码检验，但仅证明来源链结构正确 |
| 引用支持与回答 | Citation Precision/Recall/F1；答案且证据链均正确的比例 | 需要独立复核的主张—证据对应和合法替代支持路径；不能只检查引用ID存在 |

COCO的检测指标及阈值采用官方评测口径，完整AP应复用[COCO evaluator](https://github.com/cocodataset/cocoapi/blob/master/PythonAPI/pycocotools/cocoeval.py)，不要把匹配框的平均IoU改名为AP。检索指标可与[NIST trec_eval](https://github.com/usnistgov/trec_eval)对齐。引用支持与回答质量分开验收可参考[ALCE](https://aclanthology.org/2023.emnlp-main.398/)；其中语义支持不能由矩形重合或词面相同代替。

## 定位协议：先明确框的对象

现存目录混有message_row、message_bubble、annotated_element。主要HTML渲染框是整条消息行，可能包含日期、昵称或头像；第一轮Pillow部分框是气泡；LabelU旧数据还含头像、时间、标题等元素。**不能拿紧贴气泡的模型框直接与整行参考框比较，再据低IoU认定模型定位失败。**

当前可先冻结message_row轨，明确要求模型输出整条消息行。若目标是精细目标检测，应为新版本另存message_bubble轨；文字块定位再单列。不同bbox_scope和对象类别分别汇报，不能混算。

坐标统一为原始图像像素xyxy：左上原点，[x1,y1,x2,y2]，连续几何面积采用(x2-x1)×(y2-y1)，不加1。归一化0–1或0–1000坐标必须显式声明再按原图尺寸转换；禁止猜测坐标空间。模型必须指出对应input_image_id/图像哈希，输入序号不当作原始证据页码，未知evidence_page仍为null。

IoU = 两框交集面积 / 两框并集面积。错图、缺框、无效输出不能从模型成功样本中悄悄删除；无效GT则单列排除理由、受影响分母并修订版本，不能让模型承担坏标注的错误。单图多个框用一对一匹配，重复框不能重复命中同一个目标；完整检测AP按官方confidence排序匹配实现。

全目标mean IoU应包含未命中的目标为0，同时报告错误图片率、越界率、漏检和误检。只计算“成功匹配的框的mean IoU”会掩盖漏检；仅报Hit@0.5也会掩盖乱报大量框。

示例模型输出（协议草案，尚未冻结为正式任务）：

```json
{
  "question_id": "q1",
  "predictions": [
    {
      "prediction_id": "b1",
      "input_image_id": "input_03",
      "bbox": [120, 300, 700, 480],
      "coordinate_space": "original_pixels",
      "bbox_scope": "message_row",
      "confidence": 0.85
    }
  ],
  "claims": [
    {"claim_id": "c1", "text": "模型的具体主张", "evidence_predictions": ["b1"]}
  ],
  "abstain": false
}
```

confidence是预测排序分数，不能仅因字段存在就宣称已校准。没有该字段的固定单框任务仍可计算定位命中率、IoU及多框F1。

## 多跳检索与完整回溯

Recall@k衡量前k条覆盖了多少相关证据，MRR衡量首个相关证据的位置。多跳题找到一条相关消息仍可能缺少关键前提，需要增加本项目的完整支持集指标：

```text
CompleteSupport@k = 1，当且仅当前 k 条结果
完整包含至少一组已认证的充分证据集合；否则为 0。
```

若{m1,m2}与{m3,m4}是两条合法替代路径，取回任意一组即可，不能强迫模型找齐两组的并集。页级充分性标注只能用于页级指标，不能冒称消息级或像素级最小性。当前V3独立认证仍0，作者提出的支持集只能做development诊断，不能据此发布正式CompleteSupport成绩。空支持集合不自动视为答对；无答案题需单列弃答正确性和错误断言率。

应检查的来源链为：主张/中间判断→消息或区域ID→图像ID与内容哈希→原始像素框。这里评测可验证的证据链，不要求模型暴露私有思维过程。

建议区分两种“回溯正确”：

1. **结构正确**：引用存在、属于当前案件和允许输入、哈希匹配、框合法、能够打开原件。由代码完成。
2. **语义支持正确**：引用内容真的支持对应主张，且必要前提完整。用独立认证的标签、替代路径和必要人工复核评分。

例如模型准确框出“我已经转账”，却回答“对方已实际到账”，即使IoU=1、链接可打开，也不能判为引用支持正确。正式端到端指标应要求回答正确、引用定位正确、至少一条认证充分路径完整；几何分与语义分仍需分别报告。

## 防止参考答案进入模型输入

软件运行时可直接使用程序生成的准确坐标；原图定位测评时必须让待测模型自己输出框。这是两个不同用途。把生成器读到的DOM框与自身比较得到IoU=1，不是模型定位能力结果。

建议分别运行：

- 原图定位轨：模型仅接收白名单题面、输入图和必要尺寸，不给参考框、作者转录或答案。
- 固定OCR检索轨：统一给所有方法同一份OCR候选；BM25与其他方法用同一候选集比较，报告OCR误差。
- Oracle转录/区域轨：使用审核侧准确转录与区域，隔离检索/推理能力上限；不把它的结果当作原图定位成绩。

Gold、历史标注、作者答案和模型predictions分目录存储，评测run绑定图像/标注/评分器/提示词版本哈希。不能把当前产品索引中的作者或金标转录作为未声明工具提供给原图测评模型。

同判决、同对话、同图、不同round、反事实和分页版本按来源family整体划分，避免近重复跨训练/测试。置信区间按案件/来源family聚合或bootstrap，不能把同案多图当成独立样本。报告语言、布局、长消息、未知时间、反事实及缺证题的分层结果。

API超时、服务失败和模型输出解析失败分别记录，冻结重试规则；同时报告计划任务数、请求完成率及模型能力指标的实际分母，避免只展示成功调用造成幸存偏差。
