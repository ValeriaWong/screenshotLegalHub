## 1. 当前基线与必须纠正的理解

实际迁入1170个逻辑图片、12172个任务（1170 KIE＋11002 VQA），另29个旧审核意见。VQA为6304个区域属性题＋4698个全图属性题，区域题涉及4180个区域ID。原始6333条rect属性包含29条bug_report，原始4209区域数也包含这29个意见区域；不能把6333全部作为新VQA题，或将4180个区域当成6304道题的分母。

现有benchmark.run只有一次旧IoU回放，没有新的benchmark.attempt、人工任务标注或任务发布。DeepSeek-V4.1-Flash-1017配置已启用且声明支持图片，但这批迁入任务尚未真实在线验收。本轮当前后端228项完整通过（含原195项及新增33项参数化链路用例）；不与上轮193/32的历史结果累加。

可复用原图托管、Task/Prompt快照、Gateway、SQLite records/jobs/idempotency/audit_events、逐题结果和审核发布。不引入独立工作流服务。本轮已补持久化依赖调度及新预测关联；legacy_replay仍只读取旧产物，与新在线关联分别保留。

## 2. 批判性评估：风险和取舍

| 风险 | 代码/数据依据与后果 | 本轮处理 |
| --- | --- | --- |
| R01：按文件名或仅按SHA连接 | freeze_task的手动新结果绑定检查图片SHA，create_run一次只有一个upstream_attempt_id；不能自动处理多图，也未完整限定同一数据/标注上下文 | 逻辑图片身份与字节哈希分开；每图显式绑定预测与下游任务，owner/数据快照/图片版本/协议一起校验 |
| R02：把区域关联当检测质量 | 旧IoU允许复用消息框；头像/金额片段与完整气泡粒度不同。即使片段完全位于正确消息，IoU仍可能很低 | 旧关联、新在线关联、人工消息检测分别命名和计分；0.6只作冻结基线，不能据此宣称KIE检测差/好 |
| R03：参考框引导被称作纯端到端 | 用参考ROI从预测消息中挑输入，相当于提供了区域定位辅助，即使不传答案也改变了任务条件 | 新链路明确标为“参考区域引导的预测文本VQA”；整图VQA对照单列，人工转录辅助继续关闭 |
| R04：低IoU/失败被筛掉后成绩虚高 | 若KIE结束后才生成“通过”的题，计划分母会变小；旧one2one还可能删掉同框不同属性 | 启动时先冻结所有所选题ID；每题终态必须存在；按区域共享关联计算，不删除属性题 |
| R05：全局题被错误地强制匹配 | 4698个全图属性题没有ROI；把它们送进IoU会误判缺框或误绑局部消息 | 区域题走关联；全局视觉题预先路由原图；文档预测文本只作明确允许的独立诊断，不能假设KIE保留了截图规范性等全部证据 |
| R06：本地处理失败变成服务失败 | execute在同一try内做调用、解析、评分；评分异常可能把已收到响应的attempt改为failed，再次调用会重复付费 | 将调用、解析、关联、输入构造、评分状态拆开；原始返回可用时只补本地阶段，默认不重调模型 |
| R07：全局调用阶段不能支撑依赖恢复 | Store.claim按job.phase=calling_model将过期job标未知；一份job内串多个远端请求不能细分哪个节点需恢复 | 每个计费单元独立job/attempt；父流程只调度；检查Gateway已落盘返回后再判未知；完成产物与下游outbox同事务 |
| R08：严格校验与“部分可用”混淆 | 当前kie一个坏框或缺字段会让整份parsed不可用；不能临时放松规则偷偷提高覆盖率 | MVP采用strict.v1，任何必需消息无效则依赖阻塞；保留逐消息错误。未来partial.v1须独立输入协议、分母和对照验收 |
| R09：自动扇出没有真实预算约束 | 一图可带多题；已有单次Run限制500题；无默认输出token上限时仅靠调用次数无法保证硬费用上限 | 预览静态最大调用数、分阶段并发与原子额度预留；沿用模型配置中的token/价格。费用未知显示未知，软止损与硬上限区分 |
| R10：重评和latest选择污染报表 | results取最新Score，但分类仍读run.tasks旧target；classification_report按本次观测标签建集合 | 引入固定ScoreSet/target_hash/字典版本；混淆矩阵读所选ScoreSet目标；固定标签空间，禁止不同参考/量表混合求平均 |
| R11：对照轨道失败后偷偷替换 | 从匹配文本回退整份预测/人工文本/图片，会改变输入条件，也掩盖上游问题 | A阶段每轨道只允许冻结的输入范围；无框、低IoU、服务未知分别记录阻塞原因；B阶段可另建预声明、计费可追溯的补救策略，不能覆盖首次结果 |
| R12：自动完成被误认为已审核 | 82个补图身份未确认，人工消息级KIE参考、部分字典和旧VQA论文评分器缺失 | 生产试跑只用明确来源的开发样本；无目标只报告结构/覆盖，旧参考分显式标注；不自动认证/发布，不宣称论文等价复现 |

R01/R03/R04/R06/R07/R09/R10为P0：先定契约与恢复，再增加自动执行按钮。R02不是仅调低阈值可以解决的问题。可附算IoA/包含率作为开发诊断，禁止用它替换已冻结IoU后沿用原成绩名。

## 3. MVP运行拓扑与输入边界

~~~mermaid
flowchart TD
  P[选择范围并冻结计划/预算] --> K[每图KIE调用：仅原图]
  K --> V[原始返回落盘/结构和坐标校验]
  V -->|有效预测| M[区域题：参考ROI与预测消息关联]
  M -->|达到固定阈值| I[只取绑定的预测消息构造VQA输入]
  M -->|无消息/零交集/低IoU| X[保留题目，记录未执行原因]
  P --> G[全局视觉题：直接原图VQA，预先独立规划]
  V -->|无效/失败/未知| X
  I --> Q[逐题在线VQA]
  G --> Q
  P -->|显式勾选对照| B[独立整图VQA，不等待KIE]
  B --> S[分别计分/质量待评]
  Q --> S
  S --> R[逐图/逐阶段/逐题汇总与审计]
  X --> R
~~~

主链：kie_image → association-iou.live.v1 → vqa_matched_message。全局视觉题预先走vqa_image_full，不等待KIE；图像规范性、截图类型等不能只看抽取文本。只有题目输入协议明确允许时才单列kie_image → vqa_document_prediction诊断。现有vqa_predicted_text表示整份预测，不直接改其含义；新输入采用benchmark-input.v2，显式input_scope=matched_message/document_prediction/full_image。区域题的整图视觉对照另列。MVP不加入新的多图、动态LLM出题、裁图、人工转录或自动模型裁判。

“生成VQA输入”指用冻结的已有题目与字段定义填充模板，不是让另一个模型重写题目。区域答案、审核意见、判决书、旧matched_message、旧保存Prompt和人工转录均不进入答题请求。匹配可以使用参考几何/区域ID，严禁读取参考answer作为候选消息或文本兜底。

全局视觉输入使用原图及冻结问题/定义，不能以KIE转录替换图像。文档预测诊断保留全部预测conversation，并声明可能缺失界面信息；局部文本输入只包含实际选中的预测消息及按协议允许的timestamp/speaker/content/image/transfer/file。未提供的上下文不从原文补齐。模型text/图文轨道以及参考区域引导身份必须在结果和导出中可见。

## 4. A阶段记录与绑定（已实现）

继续使用现有SQLite。以下契约已集成现有Store/Worker/Gateway；小型任务/输入保存SQLite不可变记录，原始响应/清单/报告文件存路径和哈希：

| 记录 | 必须冻结/保存 |
| --- | --- |
| benchmark.pipeline | owner、scope=development/official、数据/发布快照、全部逻辑图片/题目ID、输入轨道、阶段模型/Prompt快照、关联/解析/评分版本、失败策略、预算、父分支、计划SHA |
| benchmark.pipeline.node | pipeline_id、image_key、question_id或region_id、stage、依赖node/产物SHA、输入recipe版本、状态、attempts、lease/outbox引用、未执行原因 |
| benchmark.prediction | KIE原始响应引用/hash、实际请求hash、解析器版本、消息原始顺序与稳定ID、原值/归一化框及变换、每条验证错误、eligible_for_dependency |
| benchmark.match | image/annotation/region/预测SHA、算法/epsilon/阈值/坐标协议、所有必要关联结果、最佳消息ID及原始索引、IoU/原因、并列策略；无匹配也落行 |
| benchmark.input | 题目/定义/模板/Prompt版本、匹配引用或文档预测引用、input_scope、reference_guided标志、实际请求白名单和SHA；目标答案单独保存 |
| benchmark.attempt / benchmark.score | 复用原始调用与追加评分；新增node/绑定/score_set引用。调用状态与格式/语义/评分状态分开 |
| benchmark.pipeline.report / ScoreSet | 固定题目集合、所用Score ID/目标SHA/字典/量表版本、分组维度、分母、覆盖、成本完整性与结果SHA |

image_key绑定owner＋dataset_snapshot＋logical_image_id＋asset_sha＋图像坐标/方向版本。相同字节的不同逻辑图片仍分别保留任务、来源和案件组。默认每个需要KIE依赖或显式选择KIE任务的逻辑图一个KIE节点；只有全局视觉题的图片无需凭空增加KIE调用。若未来复用同字节推理，只能显式启用，完整输入/模型/Prompt/输出协议相同且同owner，账本注明reused_from。

缓存键不能只有图片SHA：KIE至少包含实际输入/图像版本、Prompt、模型参数及输出schema；关联还含预测与标注几何版本；VQA还含题目、字典、输入范围、选中消息、Prompt和模型。公开跨账号缓存禁用。普通恢复不跟随任何latest。

解析/关联/构造输入为本地可重放阶段。每次提交“阶段产物＋节点终态＋下游outbox”使用同一数据库事务和租约校验。文件先原子写入并验SHA，数据库仅引用已完成产物。records增加经实测必要的owner/pipeline/image/stage表达式索引；结果分页查询，不反复全表扫描或在父记录里重写万条任务JSON。

## 5. 关联协议决策

1. legacy_replay保持原6333条回放，不接新模型响应、不改旧文件/分数。源算法兼容性的确定性检验继续逐条比较。
2. association-iou.live.v1使用新KIE预测，只接有限、合法、坐标空间一致的框。采用旧公式（分母+1e-9）、属性/区域各自最佳消息、严格大于才替换、并列保留原预测顺序首项、允许多属性复用消息。阈值0.6为本轮冻结基线，正式接受前仍需语义校准。
3. 相同物理region可只计算一次，但为6304个区域属性题各自保存绑定；29条评论不产生答题节点。全局题关联为not_applicable，不能记成缺框。
4. no_message、zero_overlap、below_threshold、invalid_geometry、matched分别记录；reference_status是独立维度。开发运行可使用明确标注legacy_unverified且几何有效的旧ROI，正式运行须当前已审核快照，不把未复核自动当坏框或认证。未过阈值的区域题不调用匹配文本VQA，保留blocked_no_match及原计划分母。无参考/不成立的参考几何应记invalid_reference，与模型漏检分开。
5. 新消息检测precision/recall/F1仍需人工消息级参考，并使用独立一对一协议；不能将本关联的通过率当作其F1。
6. 不从在线输出重估阈值、不选择最高IoU那次KIE重试作为“代表成绩”、不启用旧one2one删行。新KIE重试是新分支，关联和所有受影响后代重建，原分支可继续审查。

## 6. 调度、预算与恢复

父流程冻结静态所选题清单和依赖recipe；KIE尚未完成时显示“输入待生成”，不能伪造实际输入hash。原始响应/预测冻结后，才物化下游真实请求与hash。区域/全局/对照节点从启动时已在计划中，不在看到模型结果后挑题。

每个外部请求一个独立计费attempt及job；本地阶段独立可恢复。发送前事务预留调用额度、核对取消和租约；网络往返期间不占SQLite写锁。平台不能承诺供应商端exactly-once：调用中断且没有可证明返回时记unknown，默认不重发；若Gateway已有与该节点/请求/hash一致的完成响应，则只恢复本地阶段。

通用job.retry入口不得绕过父流程直接重发pipeline节点，停止/恢复/重试只能经其有范围和预算的命令。重试最小失败范围：解析/关联/评分故障只补本地；仅显式选择重试远端节点才再次调用。重试KIE会创建新预测分支及新的关联/输入，下游旧答案仍绑定旧预测；重试VQA沿用其固定上游。重评换金标/规则只新增ScoreSet，不触发模型。重用任何实际请求响应都显示来源，不算新调用。

取消在发送前生效；已经发送的请求不能宣称撤回或零费用。停止后禁止后续请求排队/发送，已返回响应照常保存；未知请求保留未知。局部失败默认只阻塞该图所依赖题，其他图与本图预先独立规划的全局视觉题继续；鉴权失败、来源/绑定被破坏或超过预算触发全局停止；具体策略在计划中冻结。

调用上界按每个模型/轨道分别计算：N_KIE＋N_局部VQA＋N_全局VQA＋N_显式对照＋N_显式重试授权。关联不计模型调用。一次模型、全部现有任务、不加对照/重试的未筛选上界为1170＋11002=12172，不能用“1170张图”当费用规模。500任务的现有Run上限需通过分页manifest和有界子作业解决，不能简单去掉验证后一次写入巨大payload。

输入/输出单价和可选输出token上限继续属于模型设置。输出上限为空时不注入默认max_tokens；此时成本估算/运行后止损是软约束，不能承诺绝对费用封顶。需要硬费用控制时，另明确可计算的输入/输出边界、单价和供应商限额。usage缺失或调用未知时cost=null/partial，不能按0继续宣称预算安全；默认停止进一步计费直到显式处置。

## 7. 汇总与可理解性

主页面先回答：选了多少图/题、走到哪一步、还有多少未调用、为什么受阻、下一步能做什么。每图展示“KIE → 关联 → VQA → 评分”，点击可看实际原图、参考框/预测框、所选消息与模型实际输入；默认不显示哈希/英文状态作为主要说明。

预算预览、启动、节点物化、发送/返回、局部失败、停止、恢复、显式重试、重评、金标/Prompt修订和导出都进入可检索审计。完整流程、运行历史、审核台和生成反馈遵守现有产品边界；质量Prompt及质量意见仍由审核台维护，生成Prompt仍在生成台。

报表必须同时有：阶段成功率、服务/结构/关联覆盖、固定题目分母、匹配后条件质量、完整链路正确产出率、费用/延迟及完整性。按KIE生产者模型/VQA模型/输入轨道/字段/数据用途/参考版本/评分协议分组。无独立金标只报告参考诊断；金额、身份、开放分析不能混成一个无说明的总准确率。分类标签空间在计划冻结；更换目标的重评必须用同一ScoreSet的目标生成混淆矩阵。

## 11. 三种评测方式与无参考输入边界（A引导/整图已实现，B预测证据与oracle待开发）

| 方式 | 解题允许输入 | 参考材料用途 | 声明边界 |
| --- | --- | --- | --- |
| e2e_image / e2e_predicted_evidence | 原图、可独立理解的问题、系统自己的预测；可按冻结规则检索预测消息/裁剪预测区域 | 参考框、答案、父子关系只在输出冻结后参与独立评分 | 可称端到端任务流程；多模型/多阶段构成须完整披露，不能称单模型独立能力 |
| reference_guided_prediction | A阶段参考ROI挑出的预测消息，及协议明确允许的其他输入 | 参考几何参与输入选择，答案仍禁止进入请求 | 参考区域引导的VQA；作为定位辅助诊断，不能并入端到端排行榜 |
| oracle_text_diagnostic | 已人工核对的正确文本和问题 | 明确提供了人工辅助 | 仅诊断输入识别瓶颈；继续默认关闭，未实现/未批准实际调用 |

现有区域视觉对照只有通过问题可独立理解检查，才能声明为e2e_image；reference_guided=false这个布尔值本身不足以证明没有间接帮助。全局视觉题也须检查问题/定义/metadata，不能仅因发送整图就自动取得端到端身份。

B0逐题维护question_origin、source_task_id、question_version/hash、eligibility、歧义原因和人工审核。诸如“此框/region_17里的金额”不能原样迁为无参考题；应改为图片中可辨认的时间/说话人/事件描述，不能把待回答事实写进问题。无法唯一指向的题标ambiguous或不适用，记录改写/排除原因与题量；不得看模型错误后挑题。改写后是新任务版本，旧guided结果不直接作为配对对照；两种方式须重用同一经审核的问题版本才能配对。

服务端为解题阶段提供独立只读输入投影：仅允许asset、问题/公开定义、预测产物及冻结配置。禁止参考几何、答案、人工parent_message_id、标注序号/顺序和审核意见经metadata、缓存、检索或裁剪坐标进入。评分器另取ReferenceSnapshot；前端审核侧可看参考不等于后台答题可读参考。不以只扫描Prompt中的答案字符串代替输入来源隔离。

防泄漏验收使用固定原图、问题和已保存的预测/模拟响应，扰动评分侧参考框/答案/标注顺序；端到端各解题节点的实际请求hash、候选与路由必须不变，评分允许改变。真实服务的随机响应不要求逐字一致。问题版本变更不属于这个不变性测试。

## 12. 匹配粒度与LLM/工程职责（新增）

先在审核台抽样核对message、text_span、avatar、transfer_card、amount、attachment的区域语义及父子关系。检测质量要求同粒度参考/预测的一对一协议；属性归属允许多对一或跨消息多证据，不能沿用“一个参考属性独占一个预测消息”的删行逻辑。

association-iou.live.v1继续作为A冻结基线。开发诊断可新增containment-diagnostic.v1：intersection/area(reference_fragment)，同时显示预测/参考面积比、类型、中心/阅读顺序及人工归属；整图大框覆盖小区域是必测反例。阈值、权重和类型规则在开发集校准后冻结，未审核类型不得当作可靠真值。包含率不替代检测IoU，不将它生成的成绩沿用旧协议名。不能在端到端候选选择中使用这类参考侧诊断。

B1最小闭环：原图KIE → 预测消息/对象及关系 → 确定性候选检索 → LLM从候选ID中选择单条或多条证据并答题 → 独立评分。首版将证据选择和回答合在一次VQA请求，不预设额外重排服务；是否拆成两次须有消融收益和新调用预算。候选数/排序、上下文范围、预测对象类型和关系规则在运行前固定，候选召回率在输出后用人工参考诊断。

工程负责坐标空间、消息稳定ID、候选范围/截断、引用存在性和原文一致性、输入白名单、依赖/预算/恢复及评分守恒。LLM负责语义识别、指代/回复/交易关系和跨消息推理；不承担最终几何校验、修改金标、选择最好分支或宣布费用安全。解题允许原图+预测裁剪须显式input_scope；坐标来自预测并保存变换，不能借审核框补定位。关系图先用普通结构字段，不引入图数据库。

LLM返回answer、evidence_message_ids、证据类型以及abstention_reason；文字证据提供quote/span，视觉证据指向预测对象/框，不编造不存在的转录。服务端核验引用ID存在于本次候选，引用文本确来自冻结预测，禁止虚构ID/原文；引用真实仍不等于能推出答案，语义支持需独立核对。支持多证据和“不足以确定”，不强迫每题都选最高重合单条消息。模型自报confidence只作附加字段；实际选择风险由开发集上的覆盖/错误率、候选歧义和人工复核校准。

## 13. 分母、证据和成本的补充口径（新增）

每个题/方式保留N_planned清单和互斥执行状态，参考有效性独立。N_ref在冻结参考版本/资格后确定，且不随模型输出调整。收到有效参考题的响应子集记N_response_ref；按冻结评分规则处理坏格式/弃答，不能把它们从条件分母删除。

以下例子采用预先固定的二值正确性协议；金额/分类/开放量表仍分开，不强行把分级量表混成二值总分。示例：100道有效参考题，70道收到响应且均已完成评分，63道正确、25道无匹配、5道上游失败：响应覆盖70%，条件正确率63/70=90%，完整正确交付率63/100=63%。三者同时展示；低IoU/无匹配/上游失败不删题，也不把原始未知答案评分伪造为0。

如果开放题等待人工/量表，不能把“尚未判定”当“答错”。另列N_scored_ref/N_ref和待判定数；完整正确交付率只在评分完备时发布点估计，否则已确认正确数C与已返回但待判定答案数U形成区间[C/N_ref, (C+U)/N_ref]，标注未完成，不据此排行；该区间不是统计置信区间，失败/阻塞不计入U。无效/未确认参考单列数量和原因，禁止通过模型输出触发参考失效。追加参考修订须新ScoreSet，并保持旧结果可查。

答案正确、定位/证据正确分别评分；有人工证据参考时另报联合成功率（两者同时达标），无参考则不虚构证据准确率。低IoU可表示粒度不一致或定位问题，不自动把一条已独立判对的整图答案改错；反之答案碰巧正确不能自动算证据正确。引导/端到端差值只作瓶颈线索：输入内容和上下文不同，不直接认定差值完全来自定位。

首次执行与补救后结果各自保留，失败attempt不会因新分支成功消失。预算/费用覆盖所有实际请求，包括选择、修复、裁判和未知调用；比较同时报告每计划题平均费用/延迟、总费用、调用数及费用完整性，禁止只对成功题或最终attempt计费。跨方式总费用可记共享KIE真实支出，但分摊方式须固定，不能每个方式重复当真实账单相加。

## 15. 第二轮批判性结论与停止条件（新增）

[第二轮批判评估](../../reports/kie_vqa_pipeline_plan_revision_20261024/CRITICAL_REVIEW.md)新增R13–R22，共22项风险；这是设计评估，不是10个已复现软件缺陷。最先解决题目独立可理解、解题/评分隔离和评分完整性，再追求更高匹配率或更多LLM步骤。

增加LLM重排不保证改进：候选没有正确证据、问题本身歧义或参考粒度错误时，模型无法可靠补救；增加调用反而可能产生引用幻觉、费用和恢复复杂度。必须与整图直接回答及冻结的简单检索基线做同题比较，收益不成立就保留简单方案。

B1只有当输入来源隔离、问题资格、候选/证据有效性、分母/费用守恒和对应本地验收完成才可声明软件交付。真实运行证据按各启用方式单独留存，不用A的G3代替B；质量结论仍需G4。全部区域低IoU时先审核粒度和坐标，不靠调低阈值让烟测变绿。未评分足够完整、重复/来源隔离未完成或补救预算无法解释时，不发布优劣排名。
