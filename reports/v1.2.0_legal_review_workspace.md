## 设计与职责

实际读取用户 GitHub 的 `ValeriaWong/agency-agents`，采用 UI Designer、Frontend Developer、Backend Architect 三个角色。角色文件与对应 blob SHA 记录在 [来源记录](../docs/agency-agents/SOURCE.json)，MIT许可一并保留。主 agent 独立整理现有证据内容、复核提示与引用，不将内容提取交给角色 agent。

以藏蓝、米白、青绿色重做案件库、单案工作台和新增批注页。桌面左侧是待办队列，中间是可滚动的原图与引用，右侧是判断、提示和批注。原图无需另找文件；直接引用的原始像素框自动定位，支持切换来源图和放大完整原图。没有直接引用的事项在原图上方明确提示证据缺口，相关截图仅供上下文核对，不绘制虚假的引用框。

## 复核操作

每条区分原始判断、当前建议、人工决定及历史批注。法律节点可展开现有法条内容并核对适用日期和版本；尚待核实的身份、实际付款、数量、完整价款及交付等问题明确保留。助手对照原文提出的修订仍是待人工复核内容。

支持确认、保存修订、驳回、稍后复核，完成后自动选择后续待办；可撤销并重新批注、查看历史和导出该案批注。编辑后的判断不会被“确认”按钮悄悄丢弃，需使用保存修订。快捷键：1确认、2进入编辑、3驳回、4稍后复核，J/K切换事项；输入框内不触发决定快捷键。

本机草稿自动保存，刷新恢复；正式提交存入独立SQLite批注库，不改写原图、原始模型响应或原有分析。版本冲突返回409，保留当前草稿，需先核对最新内容并重新批注。来源或判断内容变化会使此前状态失效为“原文已变更”，历史决定仍可追溯，不能继续导出为有效的已复核文本。批注历史通过数据库事务及只追加约束保存；这不是外部认证或防管理员篡改的审计系统。

## 当前范围

案件库有316组材料，当前仅两个案件已有分析。默认批注队列为48项：合同条款16项、法律节点13项、法律解释6项、问答判断5项、事实线索8项。默认不为未分析案件编造法律判断；显式打开未转录案件时可生成转录覆盖缺口待办。以后新增分析或问答会按该案材料生成新的待复核事项。

正式库验收时48项全部待复核，未写入测试决定。现有法律解释、视觉转录与法条仍需用户核对；来源可定位不等于判断正确，也不等于专业法律审查已完成。中英文切换覆盖操作界面及已有双语提示，证据原文和现有中文分析不会被自动改写为另一语言。
