# 图片审核、判决书侧栏与审核评论

2026-10-24（Asia/Singapore）。

入口：http://127.0.0.1:18431/review.html 。

审核页现在以当前修订图片和消息坐标框为主要视图。样本字段、消息列表、题目及导入原图放在可展开区域，避免先面对整页文本表单。

## 操作

1. 选择样本后，图片直接覆盖显示消息坐标框。点击框内消息，打开该消息的文本与评论弹窗。
2. 默认勾选“锁定坐标框”，可编辑文字或添加评论，拖拽不会改变坐标。
3. 文本纠正后点击“保存并重新渲染”；修改说明可选。后台保存新 revision、坐标布局、差异和持久化渲染任务，完成后更新图片。
4. 如需调整坐标，取消勾选“锁定坐标框”。拖拽框体移动，拖拽八个边角手柄缩放；方向键微调，Shift + 方向键每次 10 像素。重新锁定只停止继续拖动，仍可保存已经完成的调整。新图片或重新打开样本后默认锁定。
5. 不需要改消息时，在消息弹窗填写“审核评论”并点“仅保存评论”。整条样本的意见可在“添加样本评论 / 查看评论”中保存。评论独立记录，不产生文本 revision 或无意义的重渲染。
6. “判决书原文”按钮始终存在。点击从右侧滑出原文；未附原文的样本也保留侧栏并明确显示缺失状态，不用合成消息冒充原文。

消息编辑、坐标草稿和未提交评论一起进入本地 IndexedDB / 服务器草稿；并发冲突保留双方内容。评论单独保存后会清理对应草稿，刷新仍能看到已保存评论。

## 坐标与重渲染

坐标采用原始画布像素 xyxy；UI 根据图片显示比例映射拖动距离，页面尺寸、消息映射、非有限值及越界由后端校验。手动变更必须显式提交 coordinates_unlocked 和对应 manifest ID，并通过 expected_revision 检查。

普通文本保存沿用已有布局；渲染在固定框内重新排版，必要时缩小字号，避免默认文本纠正意外移动坐标。不会静默裁掉放不下的文字：过小框会留下明确 render_layout 失败，文字仍保存在新版本，上一成功图片保留。失败时允许基于上一成功画布解锁扩大新布局，再保存恢复渲染。

新增布局与差异保存在 SampleRevision.layout / layout_diff，渲染清单保存布局哈希、页面尺寸、message ID/bbox 与文本版本。新任务使用 pillow-chat.v2；既有图片和发布版本保持不可变。

## 评论如何用于 AI 迭代

评论保存样本 revision、message ID（可为空）、消息原文快照、图片 manifest/页/框、内容哈希、作者、时间和是否用于生成。评论同时镜像到质量记录（method=comment），不冒充评分，也不改人工审核结论。

生成台新增“使用同源样本审核评论迭代”，默认开启，可预览将使用的反馈。来源样本与其生成候选的有效评论属于同一来源族；仅勾选用于生成的评论会进入下一批次。创建批次时固定 review_feedback 快照及 feedback_hash，生成请求实际携带该快照。后续评论修订不会暗改正在运行的批次。模型仍须遵守来源约束，不因评论补造无依据事实。

评论及使用快照保留在审核历史、质量历史与批次导出包里。评测输入继续使用明确字段白名单，不把审核评论传给被评测模型。

- POST /v1/review/samples/{id}/comments

- POST /v1/studio/batches：use_review_feedback、feedback_ids；批次结果保存 review_feedback 快照
