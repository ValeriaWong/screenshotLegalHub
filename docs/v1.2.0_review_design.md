# Evidence workspace · v1.2.0 review design

UI Designer handoff, 2026-10-04. Scope: shared visual system and the `/review` interface. Legal interpretation and evidence extraction remain owned by the corresponding implementation roles.

## Product promise

**让每一项判断，回到证据。** Keep this Chinese slogan exactly, including punctuation. A reviewer should be able to locate the original, understand the proposed assertion, and record a decision in one focused workspace. Confirmed review means a human has reviewed that assertion; it must not imply judicial authentication, legal finality, or a proven contract.

The visual language is a quiet legal workbench: deep navy chrome, warm paper surfaces, teal for an active connection, amber for an open question, and restrained red for rejection or a save failure. Use actual source imagery as the focal visual; avoid stock illustrations, decorative AI imagery, or simulated evidence. Titles and labels describe the user's task. Keep implementation details, raw file paths, storage locations, and model payloads outside the product flow.

Use `--wb-font`: Segoe UI, PingFang SC, Microsoft YaHei, system sans-serif. The hub's slogan and large metric numerals may use system serif for an editorial accent; all review content stays in the sans-serif stack. Body/editor text 14–15px with 1.8 line-height; section headings 16–18px; page title 24–30px; supporting labels at least 11px. Avoid tiny all-caps metadata in the reading flow. Source numbers use tabular numerals.

Use a 4px spacing rhythm: 4, 8, 12, 16, 20, 24, 32. Inputs/buttons are at least 44px tall; an icon-only action has a 44px target and accessible name. Radii: 8px controls, 12px panels, 18px dialogs. Shadows distinguish layered surfaces, not every nested field. Shared transition duration is 220ms; feedback entrances 180–280ms. Disable nonessential animation and smooth scrolling under `prefers-reduced-motion`.

## Review workspace structure

The header provides a return link to the case, the review title, case name, saved state, and progress such as `已核验 8 / 24`. The page starts with the exact slogan and one practical line: `核对原文、修订判断，并记录你的决定。` Avoid a second promotional hero on this task page.

At widths above 1050px, use three columns: **272px queue · flexible evidence (minimum 380px) · 390px assertion/editor**, with 16–20px gaps. At a viewport too narrow for these minimums, switch to the responsive mode. The source and editor must remain readable without horizontal page scrolling. Each panel begins with a meaningful heading. Keep the original image contained at natural aspect ratio; a short screenshot may center in its stage and a long one must remain fully available through scrolling or a readable full-image view. Do not crop away evidence to fit a fixed card height.

| Area | Contents and behavior |
| --- | --- |
| Queue, left | Status filters with counts, text search, items with legal type, assertion preview, evidence count, status, and one clear current selection. Default to pending. Show the active item with teal surface and a left accent; use text and an icon in addition to color. Completed items remain accessible through filters. |
| Evidence, center | Source selector with stable numbered labels `[1] 原图 03 · 消息 12`; full screenshot; bounding box overlay for the selected exact quote; original quote beneath the image; surrounding conversation in order. Display speaker/time only when present in source data. Allow zoom/full original and source switching without losing edits. |
| Assertion/editor, right | Proposed legal assertion, legal type, facts versus interpretation, evidence state, source citations, qualifications/uncertainty, and editable review note. Editing keeps the original proposal distinguishable from the reviewer's amended wording. Do not manufacture confidence percentages. |
| Decision bar | Sticky near the bottom of the editor on desktop; sticky full-width on responsive layouts. Four labeled actions: `确认` primary teal, `修订并确认` secondary, `不采纳` restrained red outline, `稍后处理` neutral/amber. Add previous/next or explicit next-item navigation without hiding outcome feedback. |

Source numbering is stable within the displayed assertion. Quote `[1]` means the same source in the assertion, source selector, quote block, and image. Clicking any citation selects its source and exact quote and moves to the evidence tab on a small screen. Coordinates must be mapped to the original image size, so the overlay follows resize/zoom. If a source, original image, or bounding box is missing, explicitly show `原图暂不可用` or `未提供定位框`; never draw a fabricated box or silently cite a different message.

## Decision and editing interactions

1. Selecting an item updates evidence, proposal, and review state together. Announce the selected title and queue position through a polite live region.
2. `确认` records acceptance of the currently displayed proposal. `修订并确认` records the amended text and note; focus the editor if the action is chosen before amendments. `不采纳` records rejection with a brief reason, and `稍后处理` preserves a note without counting the item as accepted. All successful decisions update progress and item status only after the server confirms the write.
3. Keep edits as the reviewer changes tabs or sources. Autosave an editable draft after a short pause (approximately 600ms); show `正在保存…`, `已保存`, or `保存失败 · 重试`. Draft save must not silently confirm a decision. Never claim a saved draft before persistence succeeds. Preserve unsaved text on recoverable failures.
4. When proceeding to another item after a decision, announce the result and move focus to the next item's title. Show a concise way to reopen the completed item; no disappearing confirmation toast should be the only outcome record.
5. Concurrent review uses a revision/version token. If a write conflicts, show `此项已由其他核验更新。你的修改已保留。` and the current saved review alongside the local draft. Offer `查看最新` and a deliberate reapply path; do not overwrite the other review or auto-retry a stale decision. Conflict keeps final actions disabled until resolved.

Keyboard shortcuts are optional accelerators with visible help: `J` / `K` next/previous queue item, `C` confirm, `E` edit, `R` reject, `D` defer, and `?` shortcut help. Do not fire single-key shortcuts in input, textarea, select, contenteditable, when a dialog is open, or with Ctrl/Alt/Meta. A rejection shortcut opens the reason field; it must not submit an unexplained rejection. Every shortcut has an ordinary button equivalent.

## Responsive behavior

At 1050px and below, use three working tabs: `待核队列`, `截图证据`, `判断与记录`. They are semantic buttons/tabs with selected state and associated panels; implement Arrow keys/Home/End if using ARIA tab roles. Default to evidence when opening a specific item and to queue when no selection is available. Selecting a queue item opens evidence; clicking `修订` opens the editor. Preserve selection, draft, source, zoom position where possible, and save state across tab changes.

At 720px and below, use 16px horizontal padding and compact case/progress header. The decision bar wraps four full text actions into a 2×2 arrangement with 44px minimum targets, plus safe-area bottom padding. Provide enough panel bottom padding that the bar never covers the final note or citation. Long quotes and identifiers wrap; no source or editor content becomes a 200px-wide side-by-side column. Users can switch tabs or return to queue without surrendering a draft.

## States, accessibility, and design QA

Empty pending queue: `待核项目已处理完` with a button to all reviewed items. A case with no assertions: `暂没有可核验的判断` with a route back to readable originals. Loading uses structural placeholders without fake quotes. Failed load offers a retry while preserving existing drafts. A partial-source assertion remains visible with an amber limitation and lets the reviewer defer; it must not imply all evidence was inspected.

Keep visible labels on all fields, semantic headings, clear focus rings, logical queue → evidence → editor → decision order, and `aria-live="polite"` for saved state/decision results. Set `aria-busy` during writes, avoid repeat submissions, and trap/restore focus for modal dialogs. Use text as well as color for pending/confirmed/amended/rejected/deferred states. Distinguish a confirmed assertion from an original quote visually and semantically.

Accessibility acceptance targets are normal-text contrast at least 4.5:1, large text 3:1, visible focus and controls, 44px touch targets, meaningful screenshot alt text, full keyboard operation, and readable 200% zoom. These are design requirements, not a declaration of audited conformance. Validate actual rendered contrast, focus management, reflow, source overlay alignment, long Chinese/English text, keyboard guards, reduced motion, network errors, and concurrent conflicts in implementation QA.

Shared theme changes existing hub/case typography, color, panels, navigation, buttons, source quote readability, and responsive inspection stacking while retaining existing DOM IDs and classes. It adds no font/image dependency and performs no evidence extraction or model call.
