# 按图 KIE → 关联 → VQA 操作说明

2026-10-25。A阶段实现，默认按样本完整运行；[开发计划](../ai_docs_center/KIE_VQA_PIPELINE_PLAN.md)、[交付与验收记录](../../reports/kie_vqa_pipeline_implementation_20261024/REPORT.md)。本页说明软件行为；B阶段无参考证据选择、自动补救/partial解析/模型裁判尚未交付，真实在线小批验收另列。

## 启动一轮

1. 打开评测台的“新建评测”，先选图片。样本列表限制在可滚动区域内，搜索、翻页和刷新仍保留勾选。
2. 点击“下一步：选择模型”，再选模型、设置本轮调用上限并预览。流程名称、规则版本、整集运行和对照/参考用途放在“规则与更多设置”；缺少规则时可准备默认规则，此操作不调用模型。
3. 核对预览的图片数、KIE/各类问答题量及调用上界，再启动。配置或选择变化后须重新预览，调用次数上限不足时显示所需次数、当前上限及差额，可点击“将上限设为 N 次并重新预览”，确认后仍需手动启动。该上限与服务商账户余额无关；例如一图含1KIE＋3VQA，上界为4调用，不是1调用。token上限和单价仍从模型设置读取。
4. 启动后自动进入“运行结果”。直接打开带pipeline的链接也进入结果，不再先展示样本目录和新建表单；结论只在打开/切换该轮时定位一次，后台轮询不反复抢焦点或滚动。
5. 先看已返回/计划、未交付数量和费用完整性。存在未执行步骤时，可点“查看未执行原因与原图”；详情弹窗将原图/框与问题/回答并排显示，关闭或Esc回到原位置和入口焦点。

“运行结果”中按样本查看进度，阶段筛选不改变整轮分母。统计和ScoreSet在“评分明细与统计口径”，恢复、重试、重评在单独折叠区；正常阅读不需要勾选失败重试。独立KIE/VQA与旧IoU回放在“单阶段调试”，旧问答发布评测仍在“评测配置与结果”。旧试跑/全部历史可从“全部运行历史（含旧试跑）”展开，不删除已有记录。

框的含义：橙色虚线为参考区域，灰色为预测；只有match.status=matched时，实际用于区域问答的消息才显示绿色。低IoU的最佳候选显示橙色实线并明确“未采用”，不能把候选当成已发送输入。原始返回与完整输入仍可展开；修改目标、坐标、评论及人工量表请进入审核台。

身份待核对补图默认阻止运行，缺少唯一KIE来源的样本不能完整评测；没有区域题的图不虚构IoU。正式参考运行仍须人工发布版本覆盖所选样本的全部任务；未通过独立参考/量表审核不用于正式质量排名。

每张图的KIE与每道VQA各自拥有一个持久化子任务，最多一轮模型调用；跨worker仍按冻结并发1执行。区域题等待本图有效预测；全局视觉题预先独立走原图。取消/未知/失败不会从原计划中删除。

## 看懂结果

- 区域引导问答：参考框通过冻结IoU关联选出预测消息，模型只看该预测消息及题目。它带有人工定位辅助，不能称纯端到端识别。
- 整图问答/区域题整图对照：模型看原图和冻结问题；问题独立性需另审，界面不因发送整图就自动认证端到端身份。
- 区域数与属性题数分开：同一区域的多个字段共用关联计算，各题仍保留。关联通过率不能当作消息检测F1；人工消息级参考齐备时才可计算对应检测分。
- 回答覆盖、条件正确率和完整正确交付率并列。例如100道可计分参考题，70道返回并已判定、63道正确，分别为70%、90%、63%。上游失败、低IoU、无匹配仍留在完整分母。
- 可计分参考只说明格式和评分协议可用，不能代替人工认证。开放题等待量表时不填0；显示已评分覆盖和待判定区间。量表均值、KIE按图平均F1与二值问答分开。

点击阶段可查看原图、参考框、本轮预测框、真正发送的输入和原始返回。绿色表示实际选入的预测消息，橙色表示参考区域。审核台负责改标注、评论、量表与修改理由；历史图片和原始模型返回保持。

## 失败后如何继续

| 情况 | 处理 | 是否新增模型调用 |
| --- | --- | --- |
| 已收到响应，本地解析/评分故障 | 填写原因后“只恢复本地处理”；回答计数保持，原始响应不重发 | 已保存回答不重调；正常运行中由此解锁的未发送下游仍受原预算控制，已停止流程不会重新派发 |
| 低IoU/零交集/无消息 | 查看参考与预测的粒度、坐标和原始输出；修正协议/输入后新建计划，不临时降低同一版本阈值 | 不自动调用 |
| 调用结果未知 | 先核对已保存的迟到响应；归属、请求hash和模型一致才零调用采纳 | 核对本身0；无证据时仍未知，不自动重发 |
| 流程已停，但KIE迟到返回有效 | 仅本地构造匹配/冻结输入，不发送；可显式选择问答失败分支沿用输入 | 无需重复KIE；新问答分支按明确预算调用 |
| 明确重试失败KIE | 新建分支并重建受影响的关联/下游题，保留原分支；独立成功整图题不重跑 | 按新预算，可能再次计费 |
| 明确重试失败VQA | 沿用原预测、匹配和实际输入，新分支记录父节点 | 只调用所选问答 |
| 修改目标答案后重评 | 新增固定ScoreSet；矩阵读取同一版本的目标和标签字典，旧分数保留 | 0 |
| 修改问题或引导区域 | 输入身份发生变化，须重建运行，不能离线换题后继续计原回答 | 新运行另计 |

停止只阻止后续发送；在途请求仍保存返回，不能承诺撤回或零费用。费用/usage缺失、结果未知或鉴权失败会按冻结策略停止后续计费。费用未知保持未知，最大调用次数不等于硬金额封顶。

## 留存和追查

复用SQLite的records/jobs/idempotency/audit_events，以pipeline、节点、冻结任务、预测、匹配、输入、attempt、ScoreSet和报告分别保存。模型原始响应先落盘；阶段结果、节点状态和下游作业同事务提交。图片和报告文件用SHA绑定；小型任务/输入使用不可变SQLite记录，避免逐题写小文件。

运行历史、按图结果、操作台和审计相互跳转，可根据操作、关键词、时间和对象追查。导出按独立集合保存节点、输入、唯一预测/匹配、全部尝试及评分版本，避免为每道题复制整份KIE。默认轮询只返回分页摘要，不带原始响应或base64图片。

开发集评论可用于后续生成迭代；留出集反馈不进入生成。当前源图身份、消息级人工参考、字典/专业量表和独立认证仍须实际完成，软件和模拟测试不能代签。
