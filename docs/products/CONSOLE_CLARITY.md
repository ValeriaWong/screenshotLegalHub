# 面向新协作人员的控制台说明与验收

更新：2026-10-24。受众是对项目不熟悉、没有时间先阅读技术文档的协作人员。适用评测台、合成生成台、数据审核台、流程与结果、操作审计及模型配置。产品边界仍见 [PRODUCT_BOUNDARIES.md](PRODUCT_BOUNDARIES.md)。

## 页面先回答三个问题

1. 我现在在做什么：页首说明用途；首次使用说明三个操作台的关系。
2. 目前实际完成了什么：先显示本轮结论、待审候选、收到回答和已发布数量；缺失数据保留未知。
3. 下一步去哪：从流程直接打开待审样本；评测无已发布数据时，引导到审核与发布。

日常顺序：生成待审候选 → 查看图片和判决书、修改或评论 → 保存人工审核结论 → 按需确认标准答案 → 发布固定版本 → 评测。模型意见用于辅助检查，不能代替人工审核。

## 用语和信息层次

| 原先容易误解的信息 | 默认页面的表达 | 仍可在哪里查证 |
| --- | --- | --- |
| Prompt / 哈希 / 父版本 | 生成规则或评估规则；先展示名称、Markdown内容及修改原因 | 规则历史和技术详情保留版本、哈希与依据 |
| DatasetRelease | 已审核并发布的数据 | 发布与评测详情保留原编号和快照 |
| completed / 请求成功 | 执行已完成 / 模型已返回；明确收到回答不代表答对 | 原始返回、逐次调用和日志 |
| 模型评分 / pass | 模型参考意见 / 人工审核结论；旧版本意见需重新核对 | 当前图片绑定、审核历史和原始记录 |
| null分数 / 缺失用量 | 尚未计分 / 费用未知或记录不完整 | 用量、单价快照及失败证据 |
| action / object_type / IDs | 业务动作、对象名称和打开相关页面 | 技术详情保留系统动作、ID与格式化日志 |

生成时默认突出来源、规则、模型、数量和本次要求。数据集归档、语言/平台覆盖、Seed、布局放进高级设置；不填写语言和平台时沿用来源样本。折叠不清空已有设置；折叠区必填项无效时自动展开。

人工审核默认突出发现的问题、修改建议、判断依据和图片确认；评分协议、分项JSON、模型协助按需展开。允许只评论，不强迫改动消息。人工“通过”仍需核对当前图片，不能因简化页面绕过原有发布绑定规则。

审计默认提供关键词、日期、产品和结果；对象/请求/关联编号等放在高级筛选。已生效的隐藏编号条件仍明确提示并可清除。日志详情先展示业务动作、修改内容和原因，再展开原始字段。

模型设置供维护配置的人员使用，解释每百万token单价、可选输出上限以及未知价格与免费的差别。日常协作优先选择已有模型。

## 批判性评估

原有实现把数据库结构和执行参数直接呈现在任务入口，要求用户先学会内部概念，且“执行成功”的视觉信号容易被当作质量通过。仅增加帮助文档不足以解决操作时的判断负担，因此本轮同时调整默认顺序、术语、状态说明与下一步链接。

折叠也有代价：可能让人忘记已设置的高级参数。本轮保留表单值、强制校验时自动展开，并保留运行快照以供核对；批次名称、来源内容和历史记录中的原文仍可能含技术词，未擅自重写。当前下一步建议依赖已有流程状态，不是AI对内容作出的新质量判断。

软件回归只能证明信息出现、链接正确、参数保留和审核门槛没有退化，不能证明忙碌的新用户已经理解或接受界面。真人理解测试尚未执行。

## 五分钟真人验收脚本（待执行）

邀请2–3名不熟悉项目的协作人员，使用测试样本，不预先解释术语，不代为操作。记录每项耗时、是否完成、误解的词和需要帮助的位置；不把测试样本发布为正式研究数据。

1. 打开一轮流程，说出目前结果、下一步，并区分“收到回答”“人工通过”“已发布”。
2. 从主按钮打开待审样本，找到原图、判决书及审核结论入口。
3. 不编辑消息，只添加一条修改意见，并解释它后续如何用于生成。
4. 找到一次失败/未知调用，说明原因、下一步及费用是否确定。
5. 找到规则修改历史或一次操作日志，说明自己核对了什么。

验收关注是否能独立完成、是否把模型分数当成人工通过、是否把缺失费用当成免费。任何关键误解都应驱动下一轮界面调整；当前没有真人结果，不填写虚构成功率。
